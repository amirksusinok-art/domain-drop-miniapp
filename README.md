# DOMAIN DROP

Telegram Mini App для коллекционирования **виртуальных** доменов. React + TypeScript + Vite, Node.js + TypeScript, PostgreSQL. Бот открывает приложение; сама игра работает в WebView.

## Быстрый запуск

Требуется Node.js 22 или новее.

```powershell
npm ci
Copy-Item .env.example .env
npm run dev
```

Откройте адрес, указанный Vite. Если порт 5173 зарезервирован Windows, используйте `npx vite --host 127.0.0.1 --port 42731` вместе с `npx tsx watch server/index.ts`.

Без `DATABASE_URL` development использует **PGlite** — локальный PostgreSQL в `.local-db/`, с сохранением между запусками. Это не in-memory mock экономики. В production встроенная база запрещена: нужен отдельный PostgreSQL.

Для полноценного локального PostgreSQL:

```sh
docker compose up -d
```

В `.env` задайте `DATABASE_URL=postgres://domaindrop:local-development-only@localhost:5432/domaindrop`. Миграции выполняются при старте; отдельно — `npm run db:migrate`.

`DEV_AUTH=true` включает тестового Telegram-пользователя. В production эта настройка приводит к отказу запуска. Не публикуйте dev-сервер в интернете.

## Реализовано

- Проверка Telegram initData, срок действия, непрозрачные серверные сессии; mock-вход только локально.
- 50 000 стартовых coins, первый бесплатный Spin; цена последующих зависит от выбранной зоны (например .xyz — 250, .ua/.ru — 350, .ai — 2 300, .com — 3 500 coins); ежедневные 1 000 coins.
- RANDOM за 750 coins: сервер выбирает одну из реальных зон, с отдельным Luck; Re-roll снова выбирает случайную зону.
- Навигация: Главная / Коллекция / SPIN / Задания / Ещё. На главной — бонус, обзор коллекции и реальные находки; в «Ещё» — три группы разделов и настройки. Генератор открывается при запуске.
- Серверная генерация, 81 TLD, Domain Score, 6 редкостей, Perfect Match, подробная оценка.
- Pity отдельно по каждой зоне с гарантией Rare+ к 30-му выпадению; Re-roll остаётся в исходной зоне. Дешёвые зоны имеют более высокий базовый шанс Rare+, дорогие — более высокую стоимость находок.
- Keep/Sell, восстановление pending-результата, коллекция, поиск, сортировка, теги, избранное, сейф.
- Daily Quests, XP, уровни, награды, наборы, достижения и темы без влияния на шансы.
- Аукцион с резервированием ставки, возвратом проигравшему и выдачей лота победителю.
- Scanner с тремя серверными скрытыми картами, выбором одной и показом пропущенных.
- Публичный Showcase, рейтинг коллекций, TLD-события, административная конфигурация и аудит.
- Mobile-first интерфейс, Card Decryption с посимвольной фиксацией, отдельным TLD reveal, FAST SPIN, ускорением тапом, Re-roll disintegration, опциональными звуками, Telegram haptics и reduced motion.

Одинаковый адрес может выпадать повторно: каждый экземпляр имеет свой UUID. Имя, зона, редкость, score и стоимость неизменяемы; база данных блокирует переписывание характеристик. Изменения админ-конфигурации касаются только новых выпадений.

## Проверки

```sh
npm test
npm run build
npm run economy -- 200000 random xyz ua ai com
```

Тесты по умолчанию работают на временном PGlite. Для PostgreSQL задайте `TEST_DATABASE_URL` **на отдельную пустую тестовую базу**, никогда на production. Готовый шаблон GitHub Actions сохранён в `docs/ci.example.yml`: скопируйте его в `.github/workflows/ci.yml` после подключения прав workflow. До этого сборка и тесты запускаются локально. Шаблон проверяет PostgreSQL 17, сборку и зависимости.

Симуляция измеряет платные обычные вращения с Pity; бесплатный первый Spin, Re-roll, ежедневные/quest награды и события в RTP не входят. Цель — около 80%, не гарантия для конкретного игрока. Изменение цен, весов или Pity требует повторной симуляции.

## Production

Инструкции: [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md). Архитектура: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md). Безопасность: [docs/SECURITY.md](docs/SECURITY.md).

В приложении нет настоящих платежей, cash-out и регистрации доменов. Нет Fusion, Upgrade, смены TLD и повышения редкости.

Выбор режима обязателен (реальная зона или `random`): `POST /api/spin` принимает только `{ "tld": "ua" }`. Цена и шанс берутся из серверной конфигурации. Для каждой зоны стоимость калибруется относительно её собственного распределения и Pity, с ориентиром 80% RTP при стандартных настройках. Базовый шанс и текущий шанс с Luck возвращаются сервером. Расширение зон при обновлении не меняет уже полученные домены.

Автонастройка Telegram: `BOT_AUTO_SETUP=true` при заполненных серверных BOT_TOKEN, BOT_USERNAME, APP_URL, WEBHOOK_SECRET проверяет личность бота и устанавливает меню и webhook при старте. Статус можно проверить в `/api/bootstrap` (`telegramSetup`).


## Дополнительные системы (миграция 4)

- Новые аккаунты получают 50 000 coins однократно. Баланс и welcome-сообщение сохраняются на сервере. Старые аккаунты не получают доплату. `startingBalance` меняется через админку.
- Quick Sell: уровни стоят последовательно 3 000 / 7 500 / 15 000 / 30 000 / 60 000 coins. Покупка не включает автопродажу. Правила объединяются через AND; только Common/Uncommon, без Serial, избранного, сейфа и защищённых паттернов. Продажа атомарна с выпадением, работает для SPIN, Re-roll и выбранной Scanner-карты. После раскрытия игрок подтверждает уже проданный результат; повторно продать его невозможно.
- Serial Numbers глобальны по паре name+tld, выдаются только новым подходящим выпадениям и неизменяемы. Старые экземпляры без номеров; #0001 — первый подходящий Drop после запуска Serial. Номер не влияет на цену. Искусственные лоты аукциона исключены.
- Глобальные рекорды и исторический Personal Best учитывают проданные и уничтоженные результаты. День/неделя — UTC / понедельник. Сравнение цены, при равенстве — раннее выпадение. Rarest: rarity → score → value → время. Global Feed скрывает обычные дешёвые находки.
- В «Ещё»: Quick Sell, рекорды, промокод, полная история транзакций. Inspector позволяет сохранить PNG с доменом и Serial.
- Админка: dashboard, поиск/история игроков, coins/XP/tokens/Quick Sell/Pity, ban/freeze, экономика/TLD/Pity, feature flags, Serial Registry, рекорды, промокоды и аудит с причинами. Доступ только по `ADMIN_TELEGRAM_IDS` на каждом API-запросе.
- Промокоды создаёт только администратор: в миграции и приложении реальных кодов нет. Награда фиксируется при создании; поддержаны coins, XP, tokens и разблокировка существующей темы. Лимиты и начисления атомарны, даты — серверные.
- Freeze запрещает новые экономические действия, сохраняя просмотр коллекции. Бан сохраняет имущество. Аукционные возвраты и расчёты продолжаются при Freeze, бане и отключённой функции. Maintenance закрывает обычный API, оставляя администраторов и обязательные расчёты доступными.
- Флаги безопасности сигнализируют о частых запросах/SPIN/ставках, повторных ключах, попытках промокодов и росте coins. Они не банят автоматически. Минутные счётчики запросов локальны процессу; для нескольких реплик нужен общий rate limiter.

Миграции `server/schema.sql` и `server/systems.sql` выполняются автоматически одной транзакцией при старте. Не запускайте старую версию приложения поверх новой схемы без проверки совместимости Quick Sell и неизменяемости Serial. Production не содержит тестовых наград или промокодов; тесты используют отдельную временную базу.

Навигация хранит историю экранов (включая фильтр коллекции и публичный профиль); Telegram Back сначала закрывает Inspector, затем возвращает на предыдущий экран. Звук и FAST SPIN сохраняются в localStorage с безопасным fallback. Quick Sell использует chips зон; пустой выбор по-прежнему означает все зоны. CSS старой рулетки удалён.

Миграция 5 обновляет только будущие цены и выплаты: RANDOM 750, targetRtp 0.8, явные цены зон, требования Quick Sell 0/50/150/300/500 обычных SPIN. Балансы, доменные snapshots и приобретённые уровни сохраняются. События повышают только вес TLD в RANDOM, максимум ×1.3; старые boosts ограничены. Отчёт: [docs/ECONOMY_BALANCE.md](docs/ECONOMY_BALANCE.md).
